# 🐍 [2026-01] 나만의 파이썬 소프트웨어 개발 프로젝트

## 1. 시나리오 제목
나만의 음악 취향 분석 및 플레이리스트 관리 시스템

## 2. 시나리오 (5~10줄)
 평소 음악을 자주 듣지만, 플레이리스트에 곡이 많아질수록 내가 실제로 어떤 곡을 선호하는지 객관적으로 파악하기는 어렵다.
본 프로그램은 사용자가 입력한 곡의 제목, 아티스트, 장르, 재생 횟수, 개인 평점 등의 정보를 바탕으로 선호도 점수를 계산하는 음악 관리 시스템이다. 
계산된 점수에 따라 각 곡은 정리대상, 일반곡, 추천곡, 인생곡과 같은 등급으로 자동 분류된다.
사용자는 여러 곡의 정보를 리스트 형태로 저장하고, 평균 선호도 계산, 최고 선호도 곡 찾기, 추천 곡 출력, 장르별 평균 선호도 분석 등을 통해 자신의 
음악 취향을 데이터 기반으로 확인할 수 있다.
이를 통해 단순히 곡을 저장하는 것을 넘어, 자신의 음악 취향을 체계적으로 분석하고 플레이리스트를 효율적으로 관리할 수 있는 프로그램을 구현하는 것을 목표로 한다.

## 3. 예상 기능 및 메뉴 (최소 5개)
1. 곡 정보 입력
2. 전체 곡 목록 출력
3. 선호도 점수 및 등급 계산
4. 등급별 곡 출력
5. 최고 선호도 곡 찾기
6. 추천 곡 출력
7. 평균 선호도 계산
8. 장르별 평균 선호도 계산
9. 등급별 곡 개수 출력

# 🚀 [버전별 개발 일지 & AI 협업 기록]

## 🟦 [1차 과제: V1.0] 시나리오 기획

##1. V1.0 개발 내용 :
- 사용자로부터 곡 제목, 아티스트, 장르, 재생 횟수, 개인 평점을 입력받는다.
- 입력받은 재생 횟수와 개인 평점을 기반으로 선호도 점수를 계산한다.
- 선호도 점수는 재생 횟수와 평점을 적절히 반영하기 위해 (재생 횟수 / 2) + (평점 × 10) 방식으로 산출하였다.
- 입력, 형변환, 산술연산, f-string 출력을 활용하여 프로그램의 기본 구조를 구현하였다.


##2. AI  파트너십 과정 :
- 프롬포트 요약 (1) : 주제 선정 및 시나리오 작성 과정에서 도움을 얻었다.
- 적용 내용 : 주제 후보와, 선호도 점수 분류 등급 후보 이름을 추천받아 반영하였다. 그 외 시나리오 작성 과정에서도 도움을 얻었다.
- 프롬포트 요약 (2) : 구현 코드를 얻고 수정과정을 거쳤다.
- 적용 내용 : 기본 코드를 얻고 선호도 계산 및 출력 문법을 수정하였다.


##3. Troubleshooting & 기술 회고 :
- 문제1 : input()으로 입력받은 재생 횟수와 평점은 문자열 형태이므로 바로 계산에 사용할 수 없었다.
  해결: int(), float()를 사용하여 각각 정수형과 실수형으로 변환한 뒤 계산에 활용하였다.

- 문제2 : 선호도 점수를 계산할 때 재생 횟수와 평점 중 어느 요소를 더 크게 반영할지 정하는 과정이 필요했다.
  해결: 재생 횟수와 평점이 모두 반영될 수 있도록 (재생 횟수 / 2) + (평점 × 10) 공식을 적용하여 간단한 선호도 계산 방식을 구성하였다.

- 문제3 : 사용자가 평점을 정수 또는 소수 형태로 다양하게 입력할 수 있어, 출력 형식이 통일되지 않으면 결과 화면이 일정하지 않게 보였다.
  해결: 평점은 float()로 입력받고, 출력 시 f-string의 .1f를 사용하여 항상 같은 형식으로 표시되도록 수정하였다.

## 🟩 [2차 과제: V1.0] 입출력 + 리스트 + 조건문 - 향후 작성 예정
### **✨2차 과제 내용:**
 이번 과제는 ‘음악 취향 분석 및 플레이리스트 관리 시스템’을 확장하는 것이다.
사용자로부터 곡 정보를 입력받아 리스트에 저장하고, 선호도 점수를 계산하는 시스템을 구현하였다.
특히 append(), insert(), 리스트 복사, if-elif-else 조건문을 활용하여 플레이리스트를 관리하고 곡 등급을 분류하는 로직을 완성하였다.
  * input()으로 곡 제목, 아티스트, 장르, 재생 횟수, 개인 평점을 입력받음.
  * 입력받은 곡 정보를 각각의 리스트에 append()로 저장함.
  * 선호도 점수 공식 적용: (재생 횟수 / 2) + (평점 × 10).
  * if-elif-else를 사용하여 인생곡, 추천곡, 일반곡, 정리대상으로 등급 분류.
  * AI 추천곡 AKMU의 「소문의 낙원」을 상단에 미리 정의함.
  * insert()를 사용하여 AI 추천곡을 플레이리스트 중간에 삽입함.
  * 슬라이싱 [:]을 사용하여 추천곡 삽입 전 리스트를 복사함.
  * 복사된 리스트와 삽입 후 리스트를 비교하여 데이터 변화 과정을 확인함.

    
### **🤖 AI 파트너십 과정**

1. **내용 1: 음악 취향 분석 프로그램의 2차 확장 구조 설계**
    * **프롬프트 요약:** "1차 과제로 만든 음악 취향 분석 프로그램을 2차 과제에 맞게 리스트와 조건문을 활용해서 확장하고 싶은데, 어떤 구조로 만들면 좋을까?"
    * **적용 내용:** AI의 도움을 받아 기존의 한 곡만 입력하던 구조를 여러 곡 정보를 저장할 수 있는 리스트 구조로 확장하였다.
    * 곡 제목, 아티스트, 장르, 재생 횟수, 평점, 선호도 점수, 등급을 각각 리스트로 관리하도록 구성하였다.
    * 또한 선호도 점수를 기준으로 곡의 등급을 나누는 조건문 로직을 추가하였다.
    * 이를 통해 프로그램이 단순 계산을 넘어 곡의 선호도를 판단하는 기능까지 수행하도록 개선하였다.

2. **내용 2: 리스트 복사와 insert() 기능 활용 방식 고민**
    * **프롬프트 요약:** "append, insert, 리스트 복사 기능을 단순히 쓰는 게 아니라, 프로그램 흐름 안에서 자연스럽게 활용하려면 어떻게 구성하면 좋을까?"
    * **적용 내용:** 처음에는 곡 정보를 리스트에 추가하고 출력하는 단순한 구조로만 구현하려 했다.
그러나 이 경우 리스트 복사를 사용하는 이유가 부족하다고 판단하였다. AI와의 논의를 통해 “추천곡 삽입 전 상태를 보존하고, 삽입 후 상태와 비교하는 구조”로 설계를 수정하였다.
사용자가 입력한 곡 제목 리스트를 슬라이싱 [:]으로 복사한 뒤 insert()를 사용하여 AI 추천곡인 AKMU의 「소문의 낙원」을 기존 리스트 중간에 삽입하였다.
마지막에는 복사된 리스트와 수정된 리스트를 함께 출력함으로써 데이터의 수정 전후 상태를 비교하는 데 활용하였다.
    
### **🛠️ Troubleshooting & 기술 회고:**
1. **문제 1: 리스트에 값이 이상하게 들어가는 문제)**
    * **원인:** genres.append(genres)처럼 변수 이름을 잘못 사용하였다. 이로 인해 장르 값이 아니라 리스트 자체가 리스트 안에 들어가는 문제가 발생하였다.
    * **해결:** append()에는 추가하고 싶은 실제 값이 들어가야 한다는 것을 확인하였다. 그래서 genres.append(genre)로 수정하였다.
      
2. **문제 2: 프로그램 실행 시 오류 발생**
    * **원인:** 두 번째 곡의 평점을 입력받는 코드에서 괄호가 하나 빠져 SyntaxError가 발생하였다.
    * **해결:** input()과 float() 함수의 괄호가 정확히 닫혀야 한다는 점을 확인하고 수정하였다.
이후 코드를 작성할 때 괄호와 따옴표가 제대로 닫혔는지 더 꼼꼼히 확인하게 되었다.

3. **문제 3: 리스트 복사 방식 선택**
   * **원인:** 처음에는 copy()를 사용하려 했지만, 수업 자료에서는 슬라이싱을 이용한 리스트 복사를 다루고 있었다.
   * **해결:** 수업에서 배운 내용을 반영하기 위해 backup_titles = titles[:] 방식으로 리스트를 복사하였다.
