# 🐍 [2026-01] 나만의 파이썬 소프트웨어 개발 프로젝트

## 1. 시나리오 제목
여러 사람의 취향이 모이는 공동 플레이리스트

## 2. 시나리오 (5~10줄)
 본 프로그램은 여러 사용자의 음악 정보(이름, 곡 제목, 장르, 재생 횟수와 개인 평점 등)을 입력 받아 공동 플레이리스트를 만드는 시스템이다.

입력받은 정보를 기반으로 선호도 점수와 등급을 계산하고, 같은 곡이 3번 이상 입력되면 공동 인기곡으로 판단한다.
한 사용자의 음악 정보를 분석할 뿐만 아니라, 사용자 간의 음악 정보 (장르, 평균 선호도 등)을 비교하여 취향의 유사성을 분석한다.
또한 사용자에게 부족한 장르를 찾아 AI 추천곡을 추가하고, 전체 플레이리스트의 종합 리포트를 제공한다.

 이를 통해 단순히 곡을 저장하는 것을 넘어, 여러 사용자의 음악 취향을 체계적으로 비교·분석하고 부족한 장르를 보완하여 공동 플레이리스트를 효율적으로 발전시키는 프로그램을 구현하는 것을 목표로 한다.

## 3. 예상 기능 및 메뉴 (최소 5개)
1. 곡 정보 입력
 사용자 이름, 곡 제목, 장르, 재생 횟수, 개인 평점을 입력받고 누적된 전체 플레이리스트를 출력한다.
2. 취향 비교 기능
 두 사용자간의 대표 장르, 평균 선호도, 공동 장르 개수를 비교하여 음악 취향의 유사성을 분석한다.
3. 사용자를 위한 AI 추천곡
 특정 사용자의 부족한 장르를 찾아 AI 추천곡을 플레이리스트에 추가한다.
4. 최고 선호도 곡 및 평균 선호도 계산
 전체 곡 중 선호도 점수가 가장 높은 곡과 전체 평균 선호도 점수를 출력한다.
5. 공동 플레이리스트 종합 리포트
 총 등록 곡 수, 참여 사용자 수, 인기 장르, 공동 인기곡 수 등을 종합적으로 출력한다.
0. 프로그램 종료 
 메뉴 반복을 종료하고 프로그램을 끝낸다.

- 입력, 형변환, 산술연산, f-string 출력을 활용하여 프로그램의 기본 구조를 구현하였다.


##2. AI  파트너십 과정 :

- 적용 내용 : 주제 후보와, 선호도 점수 분류 등급 후보 이름을 추천받아 반영하였다. 그 외 시나리오 작성 과정에서도 도움을 얻었다.
- 프롬포트 요약 (2) : 구현 코드를 얻고 수정과정을 거쳤다.

##3. Troubleshooting & 기술 회고 :
- 문제1 : input()으로 입력받은 재생 횟수와 평점은 문자열 형태이므로 바로 계산에 사용할 수 없었다.
  해결: int(), float()를 사용하여 각각 정수형과 실수형으로 변환한 뒤 계산에 활용하였다.

  해결: 재생 횟수와 평점이 모두 반영될 수 있도록 (재생 횟수 / 2) + (평점 × 10) 공식을 적용하여 간단한 선호도 계산 방식을 구성하였다.

- 문제3 : 사용자가 평점을 정수 또는 소수 형태로 다양하게 입력할 수 있어, 출력 형식이 통일되지 않으면 결과 화면이 일정하지 않게 보였다.
  해결: 평점은 float()로 입력받고, 출력 시 f-string의 .1f를 사용하여 항상 같은 형식으로 표시되도록 수정하였다.

## 🟩 [2차 과제: V1.0] 입출력 + 리스트 + 조건문
### **✨2차 과제 내용:**
 이번 과제는 ‘여러 사람의 취향이 모이는 공동 플레이리스트’을 확장하는 것이다.
사용자로부터 곡 정보를 입력받아 리스트에 저장하고, 선호도 점수를 계산하는 시스템을 구현하였다.
특히 append(), insert(), 리스트 복사, if-elif-else 조건문을 활용하여 플레이리스트를 관리하고 곡 등급을 분류하는 로직을 완성하였다.
  * input()으로 곡 제목, 장르, 재생 횟수, 개인 평점을 입력받음.
  * 입력받은 곡 정보를 각각의 리스트에 append()로 저장함.
  * 선호도 점수 공식 적용: (재생 횟수 / 2) + (평점 × 10).
  * if-elif-else를 사용하여 인생곡, 추천곡, 일반곡, 정리대상으로 등급 분류.
  * AI 추천곡을 장르별로 상단에 미리 정의함. 
  * insert()를 사용하여 AI 추천곡을 플레이리스트 중간에 삽입함. 
  * 슬라이싱 [:]을 사용하여 추천곡 삽입 전 리스트를 복사함. 
  * 복사된 리스트와 삽입 후 리스트를 비교하여 데이터 변화 과정을 확인함.
    
### **🤖 AI 파트너십 과정**
1. **내용 1: 음악 취향 분석 프로그램의 2차 확장 구조 설계**

   * **프롬프트 요약:** "1차 과제로 만든 음악 취향 분석 프로그램을 2차 과제에 맞게 리스트와 조건문을 활용해서 확장하고 싶은데, 어떤 구조로 만들면 좋을까?"
   * **적용 내용:** AI의 도움을 받아 기존의 한 곡만 입력하던 구조를 여러 곡 정보를 저장할 수 있는 리스트 구조로 확장하였다.
   * 곡 제목, 아티스트, 장르, 재생 횟수, 평점, 선호도 점수, 등급을 각각 리스트로 관리하도록 구성하였다. 또한 선호도 점수를 기준으로 곡의 등급을 나누는 조건문 로직을 추가하였다. 이를 통해 프로그램이 단순 계산을 넘어 곡의 선호도를 판단하는 기능까지 수행하도록 개선하였다.

2. **내용 2: 리스트 복사와 insert() 기능 활용 방식 고민**

   * **프롬프트 요약:** "append, insert, 리스트 복사 기능을 단순히 쓰는 게 아니라, 프로그램 흐름 안에서 자연스럽게 활용하려면 어떻게 구성하면 좋을까?"
   * **적용 내용:** 처음에는 곡 정보를 리스트에 추가하고 출력하는 단순한 구조로만 구현하려 했다. 그러나 이 경우 리스트 복사를 사용하는 이유가 부족하다고 판단하였다. AI와의 논의를 통해 “추천곡 삽입 전 상태를 보존하고, 삽입 후 상태와 비교하는 구조”로 설계를 수정하였다.사용자가 입력한 곡 제목 리스트를 슬라이싱 `[:]`으로 복사한 뒤 `insert()`를 사용하여 AI 추천곡인 AKMU의 「소문의 낙원」을 기존 리스트 중간에 삽입하였다. 마지막에는 복사된 리스트와 수정된 리스트를 함께 출력함으로써 데이터의 수정 전후 상태를 비교하는 데 활용하였다.

### **🛠️ Troubleshooting & 기술 회고**

1. **문제 1: 리스트에 값이 이상하게 들어가는 문제**

   * **원인:** `genres.append(genres)`처럼 변수 이름을 잘못 사용하였다. 이로 인해 장르 값이 아니라 리스트 자체가 리스트 안에 들어가는 문제가 발생하였다.
   * **해결:** `append()`에는 추가하고 싶은 실제 값이 들어가야 한다는 것을 확인하였다. 그래서 `genres.append(genre)`로 수정하였다.

2. **문제 2: 프로그램 실행 시 오류 발생**

   * **원인:** 두 번째 곡의 평점을 입력받는 코드에서 괄호가 하나 빠져 `SyntaxError`가 발생하였다.
   * **해결:** `input()`과 `float()` 함수의 괄호가 정확히 닫혀야 한다는 점을 확인하고 수정하였다. 이후 코드를 작성할 때 괄호와 따옴표가 제대로 닫혔는지 더 꼼꼼히 확인하게 되었다.

3. **문제 3: 리스트 복사 방식 선택**

   * **원인** 처음에는 `copy()`를 사용하려 했지만, 수업 자료에서는 슬라이싱을 이용한 리스트 복사를 다루고 있었다.
   * **해결:** 수업에서 배운 내용을 반영하기 위해 `backup_titles = titles[:]` 방식으로 리스트를 복사하였다.

## 🟨 [3차 과제: V3.0] 무한 루프와 메뉴 시스템

과제 내용 중 부족한 부분이 보여 코드 및 내용 일부를 수정하고, 시나리오 제목과 예상 기능 및 메뉴 내용을 현재 코드에 맞게 수정하였다.
1차 과제와 2차 과제 내용은 기존 개발 흐름을 보여주는 부분이 있어 크게 수정하지 않았고, 3차 과제에서는 1차·2차보다 발전된 메뉴 선택형 프로그램으로 확장하였다.

### **✨ 3차 과제 업데이트 내용**

이번 3차 과제에서는 기존, 한 사용자의 플레이리스트를 분석하는 시스템(1차, 2차)에서 여러 사용자의 음악 취향을 누적 분석하는 공동 플레이리스트 시스템으로 발전시켰다.
기존 코드에서는 두 곡을 먼저 입력받고, 이후 메뉴에서 전체 출력, 등급별 출력, 최고 선호도 곡 찾기, 평균 선호도 계산 등을 선택하는 구조였다.
수정 후에는 `while True` 무한 루프를 사용하여 프로그램 실행 중 계속 메인 메뉴가 출력되도록 하고, 사용자가 원하는 기능을 직접 선택할 수 있도록 구성하였다.

* `while True`를 사용하여 메인 메뉴가 반복적으로 출력되도록 구현하였다.
* 사용자가 `0`번 메뉴를 선택할 때만 `break`를 통해 프로그램이 종료되도록 구성하였다.
* 기존에는 프로그램 시작 시 곡 2개를 먼저 입력받았지만, 수정 후에는 `1. 플레이리스트 입력` 메뉴를 선택했을 때 사용자 이름과 곡 정보를 입력받도록 변경하였다.
* 기존의 개인 플레이리스트 중심 구조를 여러 사용자의 플레이리스트를 누적 저장하는 구조로 확장하였다.
* 곡 제목, 장르, 재생 횟수, 개인 평점, 선호도 점수, 등급뿐만 아니라 사용자 이름도 함께 저장하도록 `users` 리스트를 추가하였다.
* 아티스트 입력은 제거하고, 대신 사용자 이름을 입력받아 여러 사람의 취향을 구분할 수 있도록 하였다.
* 재생 횟수와 개인 평점은 따로 입력받지 않고, `.split()`을 활용하여 한 줄에서 띄어쓰기로 입력받도록 수정하였다.
* 같은 곡이 3번 이상 입력되면 해당 곡을 공동 인기곡으로 판단하여 출력하도록 구현하였다.
* 기존의 “최고 선호도 곡 찾기”와 “평균 선호도 계산” 메뉴를 하나로 합쳐, 전체 선호도 분석 기능으로 정리하였다.
* 기존의 단순 등급별 출력 기능보다 발전시켜, 두 사용자의 대표 장르와 평균 선호도, 공통 장르 개수를 비교하는 취향 비교 기능을 추가하였다.
* 사용자의 플레이리스트에서 부족한 장르를 찾아 AI 추천곡을 자동으로 추가하는 기능을 구현하였다.
* 전체 등록 곡 수, 참여 사용자 수, 가장 많이 등록된 장르, 공동 인기곡 수, 정리대상 곡 수를 확인할 수 있는 종합 리포트 메뉴를 추가하였다.
* 메뉴 번호는 문자열 형태로 입력받아 `"1"`, `"2"`, `"3"`과 같이 비교하도록 구성하였다.
* `if-elif-else` 조건문을 사용하여 메뉴 번호에 따라 실행되는 기능을 구분하였다.
* `for`문을 사용하여 리스트에 저장된 곡 정보, 사용자 정보, 장르 정보 등을 순회하며 분석하도록 구현하였다.

### **🤖 AI 파트너십 과정**

1. **내용 1: 기존 개인 플레이리스트 코드를 공동 플레이리스트 구조로 확장**

1. **문제 1: 기존 메뉴 구조와 새로운 기능이 맞지 않는 문제**

   * **해결:** 함수 정의문 끝에는 반드시 콜론이 필요하다는 것을 확인하고, `def add_song(user_name, title, genre, play_count, rating):` 형태로 수정하였다. 이후 `def`, `if`, `elif`, `else`, `for`, `while` 문장을 작성할 때 콜론이 빠지지 않았는지 확인하며 수정하였다.

3. **문제 3: 함수 이름 오타로 인한 NameError 발생**
   * **원인:** 공동 인기곡을 출력하는 함수 이름을 정의할 때와 호출할 때 다르게 작성하였다. 예를 들어 `print_popukar_songs()`처럼 오타가 있는 이름과 `print_popular_songs()`를 혼용하여 오류가 발생하였다.
   * **해결:** 함수 이름은 정의할 때와 호출할 때 완전히 같아야 한다는 점을 확인하였다. 모든 부분에서 함수 이름을 `print_popular_songs()`로 통일하여 오류를 해결하였다.

4. **문제 4: `.split()` 입력 방식에서 입력 안내가 부족한 문제**
   * **원인:** 재생 횟수와 개인 평점을 한 줄로 입력받도록 수정하면서, 사용자가 어떤 형식으로 입력해야 하는지 명확하지 않을 수 있었다.

2. **문제 2: 이중 리스트 출력 화면을 어디에 넣을지 고민한 문제**
   * **원인:** 이중 리스트 출력을 위한 메뉴를 새로 만들면 메뉴가 지나치게 많아지고, 프로그램 흐름이 복잡해질 수 있었다.
   * **해결:** 별도의 메뉴를 만들지 않고, 기존 5번 메뉴인 `공동 플레이리스트 종합 리포트` 안에 이중 리스트 출력 기능을 포함시켰다. `print_playlist_table()` 함수를 따로 정의한 뒤 `print_playlist_report()`에서 호출하여, 종합 리포트를 출력할 때 이중 리스트 표도 함께 확인할 수 있도록 구성하였다.

3. **문제 3: 재생 횟수와 개인 평점 입력 오류 처리 문제**
   * **원인:** 재생 횟수와 개인 평점은 숫자로 입력되어야 하지만, 사용자가 문자를 입력하거나 입력 형식을 지키지 않으면 `ValueError`가 발생할 수 있었다.
   * **해결:** 해당 입력 부분을 `try-except`로 감싸고, 잘못된 형식이 입력되면 “예시처럼 120 4.8 형태로 입력해야 합니다.”라는 안내 문장을 출력하도록 하였다. 이를 통해 입력 오류로 프로그램이 바로 종료되는 문제를 줄일 수 있었다.

4. **문제 4: 곡 수 입력 오류 처리 문제**
   * **원인:** 입력할 곡 수는 정수로 변환해야 하는 값인데, 사용자가 문자를 입력하면 `int()` 변환 과정에서 오류가 발생할 수 있었다.
   * **해결:** 곡 수 입력 부분에도 `try-except`를 적용하였다. 숫자가 아닌 값을 입력하면 “곡 수는 숫자로 입력해야 합니다.”라는 안내 문장을 출력하고, 해당 입력 과정을 종료하도록 구성하였다.

5. **문제 5: 파일 저장 기능을 언제 실행할지 정하는 문제**
   * **원인:** 파일 저장 메뉴를 따로 만들 수도 있었지만, 메뉴가 많아지면 사용자가 파일 저장을 누르지 않고 종료할 가능성이 있었다.
   * **해결:** 0번 종료 메뉴를 선택했을 때 `save_playlist_file()` 함수가 자동으로 실행되도록 구성하였다. 이를 통해 사용자가 프로그램을 종료할 때 현재까지 입력된 이중 리스트 데이터가 `playlist_data.txt` 파일로 저장되도록 하였다.

6. **문제 6: 파일 저장 과정의 오류 처리 문제**
   * **원인:** 파일을 저장하는 과정에서 파일 경로나 저장 권한 등의 문제로 오류가 발생할 수 있다.
   * **해결:** `save_playlist_file()` 함수 안에 `try-except`를 적용하여 파일 저장 중 오류가 발생하면 “파일 저장 중 오류가 발생했습니다.”라는 안내 문장이 출력되도록 하였다. 저장이 정상적으로 완료되면 “playlist_data.txt 파일로 저장되었습니다.”라는 문장을 출력하도록 하였다.

6. **문제 7: 파일 저장 기능이 실행 화면에서 명확하게 보이지 않는 문제**
   * **원인:** 처음에는 0번 프로그램 종료 메뉴를 선택했을 때 save_playlist_file() 함수가 실행되도록 하였다. 기능적으로는 파일 저장 조건을 만족하지만, 메뉴 화면에는 파일 저장 기능이 따로 표시되지 않아 평가자가 실행 화면만 봤을 때 파일 입출력 기능을 바로 확인하기 어려울 수 있었다.
   * **해결:** 기존 0번 종료 시 자동 저장 기능은 그대로 유지하고, 메뉴에 6. 플레이리스트 파일 저장 항목을 추가하였다. 또한 elif menu == "6": save_playlist_file() 조건문을 추가하여 사용자가 프로그램 실행 중에도 직접 파일을 저장할 수 있도록 수정하였다. 마지막으로 잘못된 메뉴 번호 안내 문장도 0번부터 6번 사이로 수정하여 메뉴 구조와 안내 문장이 일치하도록 하였다.
